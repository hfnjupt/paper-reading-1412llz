# 粗读工作流

粗读用于筛选和建立论文台账，不等同于全文精读。

## 最低阅读范围

至少查看题目、作者/通讯作者脚注、规范出版信息、摘要、引言、方法核心段落、实验数据集与章节/关键图表、结论。先从引言结尾的贡献段建立方法线索，再重点查看方法部分的整体架构、模块和数据流；实验只需识别数据集与实际验证维度，无需逐表提取指标。此阅读范围是 `selected_sections`，不因全文可访问便记为精读全文。无法访问必要内容时如实降低范围或记录缺失，不得补写。

## 九列填充

1. `论文题目`：仅保留论文规范原文题目，不自行翻译替代；不得附序号、文件名标记、分区、期刊、年份、DOI、文件路径、阅读范围/状态或来源说明。论文题目本身的数字、冒号或专有名词必须保留，不能机械删前缀破坏真实题目。
2. `作者及机构`：只写作者（按论文顺序）、对应机构、期刊/会议名称和发表年份。第一作者及通讯作者姓名使用单元格内的真实加粗；明确标注的共同一作、共同通讯全部加粗，同一人兼任只写一次。通讯身份依据首页脚注/作者贡献说明等原文证据，不由最后作者、资历或邮件地址猜测。未核实通讯身份不乱加粗，在配套证据记录中说明。年份为发表年份，不把收稿、修订或接收年份自动当作发表年份；未核实可写“年份待核验”。会议论文如实写会议，不强行写期刊。删除 DOI、网址、邮箱、页码、文件路径、阅读状态等额外信息；这些来源定位保存到配套记录。
3. `摘要`：在作者及机构右侧的 C 列，同一单元格按“英文摘要：\n完整英文原文\n\n中文翻译：\n完整中文翻译”排列。逐句忠实翻译，保留数字、限定条件、缩写与结论强度；原文只能修复已核实的断行、断词及 OCR 错误，不改写或缩略。保留结构化摘要的小标题，不混入关键词、版权声明或引言。摘要中的指标和数值必须保留，“不写指标”仅适用于方法列的实验概述。无法获取完整摘要时写明缺失范围/原因，只翻译已获得的内容并标注“不完整”，不得伪造完整版本。来源及页码存配套证据记录；非英文论文没有作者英文摘要时明确说明，不以自译英文冒充原文。
4. `关键词`：任务、模态、模型、模块、损失和关键技术，避免堆砌泛词。
5. `针对的问题`：重点依据摘要及引言，以“背景：应用需求/研究动机；问题：本文试图解决的具体困难与已有缺口”组织。说明背景如何引出问题，不以方法名称或笼统“提高精度”代替问题；区分作者动机与阅读者评价，保留紧凑章节/页码定位。
6. `解决的方法`：先读引言最后的贡献列表/段落，再重点读方法正文，不直接复制贡献清单作为方法。紧凑说明“方法名称/方案→核心思想→输入到输出的处理逻辑→主要组成及分工”。最后附“实验：数据集名称/作者自建数据集描述（真实局部加粗）；涉及的验证维度”。实验维度可为定量、定性、消融、敏感性、泛化、效率、实际平台、通信链路等，只列实际开展的维度；区分数据采集平台与完整通信平台。实验摘要不写指标名称、分数、排行或提升百分比，也无需逐表数字。无正式数据集名则加粗准确的描述性名称；多数据集分别加粗，未报告时不编造。
7. `创新以及借鉴地方`：作者贡献声明与可迁移启发分开写，说明迁移限制。
8. `代码位置`：仅填已核验的官方或作者代码/项目/数据链接；没有则留空。
9. `批判地方`：作者局限、实验覆盖不足、潜在假设和不确定问题；不能把未报告写成确定失败。

除摘要保留原文段落及双语结构外，其他长单元格使用 `（1）…（2）…` 的紧凑结构，与用户参考表风格一致。粗读必须保存完整双语摘要，但不放图片；图片属于精读 Obsidian 产物。

## 证据与加粗检查

A/B/C 列的来源、作者角色依据、DOI 和实际阅读范围保存在按行/题目关联的 JSON 与 `reading-manifest.json`，不因移出单元格而丢失。E/F/G/I 中涉及论断时仍用简短证据类型标签及定位，避免为追溯信息占满表格。关键数字或指标冲突可以详细记录在配套证据中，主表仅概述冲突。

第一/通讯作者与数据集必须使用 Excel 富文本局部加粗，不能写 `**姓名**`、整格加粗或用颜色冒充。标粗只改变字体，不改变可检索的纯文本。检查实际导出的富文本片段，而非只检查输入字符串。
