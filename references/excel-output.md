# Excel 输出规范

使用 `assets/coarse-reading-template.xlsx` 作为视觉基准，或用 `scripts/build_coarse_workbook.mjs` 从 JSON 行数据生成。

## 固定列

列顺序不得改变：

```text
论文题目 | 作者及机构 | 摘要 | 关键词 | 针对的问题 | 解决的方法 | 创新以及借鉴地方 | 代码位置 | 批判地方
```

默认保持 G 列（创新以及借鉴地方）可见。若用户要求完全复刻旧表的隐藏状态，才隐藏该列。

## 格式

- 表头颜色：A/H 黄、B/C/E/G/I 蓝、D 粉、F 绿。
- 等线字体；表头突出，正文约 14pt，C 列双语摘要使用 12pt，自动换行、顶部/左侧对齐。
- 建议列宽：A 42、B 31、C 100（摘要可按长度增至 255）、D 29、E 38、F 70、G 42、H 41、I 38。
- 首行冻结，启用筛选；一篇论文一行，不合并数据区域单元格。
- 正文行高按内容调整并限制极端高度，不能截断关键文字。长摘要先自动加宽 C 列，保留一篇一行；仍无法容纳时明确报告布局失败并请求调整，绝不截断或摘要化英文/中文，也不将全文移出 C 列来冒充完成。
- URL 以纯文本完整写入代码位置列，保证可审计。
- 个别论文题目的红/绿人工标色不自动生成，除非用户提供明确分类规则。
- B 列仅第一作者及原文确认的通讯作者姓名局部加粗；F 列仅相应数据集名称/自建数据集准确描述局部加粗。使用真实 Excel 富文本，不能保留 Markdown 星号或把整格文字加粗。

## 数据接口

构建脚本接受 JSON 数组。每项使用中文列名，一般缺失值为 `null` 或空字符串；摘要不得静默留空，必须使用双语字段结构说明不可得或不完整的原因。一般单元格为字符串；需局部加粗时传入 `{ "runs": [{ "text": "...", "bold": true }, { "text": "..." }] }`，所有片段按顺序拼接为单元格纯文本：

```json
[
  {
    "论文题目": "...",
    "作者及机构": {"runs": [{"text": "第一作者", "bold": true}, {"text": "；其他作者；"}, {"text": "通讯作者", "bold": true}, {"text": "\n机构：已核验机构\n期刊/会议：已核验名称（发表年份）"}]},
    "摘要": "英文摘要：\n完整英文摘要原文。\n\n中文翻译：\n完整中文翻译。",
    "关键词": "...",
    "针对的问题": "...",
    "解决的方法": {"runs": [{"text": "方法：名称、核心思想、流程与组成。\n实验："}, {"text": "已核验数据集名称", "bold": true}, {"text": "；定量、定性和消融（按论文实际内容填写）。"}]},
    "创新以及借鉴地方": "...",
    "代码位置": "https://...",
    "批判地方": "..."
  }
]
```

摘要为字符串，固定以 `英文摘要：\n` 起始，以 `\n\n中文翻译：\n` 分隔；两部分都必须非空。脚本只验证结构、长度和导出一致性，是否完整、译文是否忠实仍需逐句对照原论文人工/阅读代理核验。旧版八列行数据必须先补齐摘要字段或明确缺失说明后再生成。

## 验证

每份工作簿同时保留行数据 JSON 和 `reading-manifest.json`（单篇也需记录来源及实际阅读范围）。以行号/题目关联证据定位和四类证据标签，不增加主表的九列。A 列只有题目；B 列只有作者、机构、期刊/会议及发表年份。摘要来源及页码也写入配套记录。A/B 的 DOI、来源页码、身份核验依据、阅读范围等写入配套记录；E/F/G/I 的重要论断定位及证据标签仍保留在对应单元格。

构建脚本生成新工作簿，不会读取或保留既有工作簿的人工修改。批量任务维护完整行数据后生成版本化 Excel；不能仅传入新增行覆盖旧文件。用户要求修改既有工作簿时，使用可导入原表的电子表格工作流。

## 运行环境

先用工作区依赖工具定位捆绑 Node.js、Python 和 `@oai/artifact-tool`。ESM 从脚本所在目录解析包；若 skill 目录不能直接解析依赖，将构建脚本与同目录 `apply_rich_text.py` 一起复制到任务临时目录，在该目录按电子表格技能指引链接捆绑 `node_modules`，再运行。不要向 skill 包内复制依赖，也不要为此自动联网安装包。

工作簿内容、布局、表格和预览由 artifact-tool 生成；原生富文本用辅助脚本在导出的 OOXML 中仅给指定文本片段写入加粗，保持单元格文本和其他结构不变（Python 标准库，无额外工作簿库）。有富文本时须以 `--python` 指定捆绑 Python；辅助脚本在保存后核对片段、加粗和原纯文本一致性。预览主要检查布局，富文本的最终依据是导出工作簿中的实际样式片段。

当前预览工具重新导入富文本后可能将局部加粗误显示成整格加粗。因此脚本使用原始未加粗布局生成预览，另对最终 XLSX 做文本回读及逐片段格式核验；不要宣称预览验证了局部字体效果。辅助脚本完成后不可再用导入后的对象重新导出，否则可能丢失原生富文本格式。

```text
node build_coarse_workbook.mjs --input rows.json --output 论文粗读-v1.xlsx --preview preview.png --python <捆绑Python路径>
```

## 交付检查

生成后必须检查 A1:In 值、扫描公式错误、渲染工作表、查看表头和至少一个最长正文行，确认无空白默认工作表、隐藏关键列、明显截断或乱码。

检查 A/B 无附加元数据；C 包含完整英文摘要及其下方完整中文翻译，逐句核对来源、数字及限定词，不混入关键词；E 包含背景和具体问题；F 有方法名称/核心思想/流程/组成、数据集及实际验证维度且实验摘要无指标。确认 B/F 的富文本范围正确，非目标文本没有一起加粗；通讯身份与发表年都可回溯。
